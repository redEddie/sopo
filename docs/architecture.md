# sopo 목표 아키텍처 — Franka식 안전한 팔이 되려면

## 0. Franka에서 가져올 것과 안 가져올 것

| Franka 구성요소 | 역할 | sopo 대응 |
|---|---|---|
| Control box (로봇 베이스 내장 RT 제어기 + 안전 PLC) | 1 kHz 루프, 안전 감시. 외부 PC가 죽어도 안전 유지 | **`sopod` 데몬** — 버스의 유일한 소유자, 고정 주기 루프 + reflex. GUI/정책이 죽어도 혼자 안전 |
| FCI (외부 인터페이스) | 1 kHz 상태 스트림 + 명령 채널 | **IPC 계층** — 상태 PUB(50~100 Hz) + 명령 REQ/REP + 액션 스트림 |
| libfranka | 외부 PC용 클라이언트 SDK | **`sopo.client`** — 파이썬 클라이언트 (lerobot 어댑터가 이 위에) |
| Desk (브라우저 GUI) | 브레이크/FCI 활성화, 안전 설정, 오류 복구, 상태 표시 | **웹 GUI (나중)** — 데몬의 구독자일 뿐, 제어 경로에 없음 |
| 외부 활성화 장치 / 비상정지 | 하드웨어 안전 | 물리 E-stop (Future work) |

가져오지 않을 것: 1 kHz 토크 제어(우리 최하위 루프는 서보 펌웨어 안에 있음), RT 커널 강제(50~100 Hz면 불필요).

## 1. 프로세스 분리 — "렉 없이 제어와 상태확인"의 실체

```
┌──────────────── sopod (제어 데몬, 버스 유일 소유자) ────────────────┐
│  고정 주기 루프 50~100 Hz (한 스레드, 다른 일 안 함)                  │
│   sync_read ─► joints ─► reflex/safety ─► clamp ─► sync_write        │
│   모드 상태머신 (IDLE/MOVE/GUIDING/REFLEX/STOPPED), 래칭 에러         │
│   워치독: 액션 스트림 끊김 → 홀드 → 토크 해제                          │
│   루프 지터/성공률 자체 측정 (Franka control_command_success_rate)     │
└───────┬───────────────────────────┬────────────────────┬─────────────┘
        │ 상태 PUB (비차단, 최신 1개만) │ 명령 REQ/REP        │ 액션 SUB (10~30 Hz)
        ▼                           ▼                    ▲
  ┌──────────┐  ┌──────────┐  ┌──────────┐        ┌──────────────┐
  │ GUI/TUI  │  │ 로거     │  │ CLI      │        │ 정책 / lerobot │
  │ (구독만) │  │ (구독만) │  │ (명령)   │        │ (액션 송신)    │
  └──────────┘  └──────────┘  └──────────┘        └──────────────┘
```

원칙:
1. **버스는 데몬만 만진다.** 쿡북 스크립트는 데몬이 꺼져 있을 때만 (포트 락 파일로 강제).
2. **루프 스레드는 I/O 외에 아무것도 안 한다.** 출력·로깅·GUI는 큐로 넘겨 다른 프로세스가. 파이썬 GIL 때문에 스레드가 아니라 **프로세스**로 나눈다.
3. **상태 발행은 절대 루프를 막지 않는다.** ZMQ PUB + CONFLATE(최신 1개만 유지) — 느린 구독자는 옛 프레임을 버릴 뿐 루프에 영향 없음.
4. **명령은 검증 후 다음 사이클에 반영.** REQ/REP 핸들러는 루프 스레드가 아니라 별도 스레드에서 받고, 루프는 사이클 시작에 명령 큐를 비운다.
5. **장애 영역 분리**: GUI 죽음 → 아무 일 없음. 정책 멈춤 → 워치독 홀드. 버스 오류 → reflex. 데몬 죽음 → 서보 자체 캡·과부하 보호가 마지막 방어선 (그래서 Max_Torque_Limit EPROM 영구화가 중요).

### 파이썬으로 충분한가
- 실측: 8모터 sync_read+write ≈ 2~3 ms. 50 Hz면 듀티 15%. 여유 있음.
- 해야 할 것: `time.monotonic` 기준 절대 시각 스케줄링(누적 드리프트 없음), p50/p99 지터를 상태에 실어 발행, 지터 p99 > 5 ms면 `chrt -f`/CPU 격리, 그래도 안 되면 루프만 C++/Rust로 — **측정 전에 옮기지 않는다**.
- 직렬화: 상태 dict는 작다. JSON으로 시작, 필요하면 msgpack.

## 2. SDK 계층 (아래부터 위로, 각 층은 아래 층만 본다)

| 층 | 모듈 | 상태 |
|---|---|---|
| L0 서보 펌웨어 | 토크 캡, 과부하 감쇠, 위치 한계, 온도 (EPROM) | 완료 (영구화 남음) |
| L1 버스 | `sopo.bus.FeetechBus` | 완료 |
| L2 관절 모델 | `sopo.joints` (single/dual/continuous), 캘리브레이션 틱↔rad, 쌍 상수 K | 1차 완료 |
| L3 안전 감독 | `sopo.reflex` (충돌·추종오차·쌍 불일치·통신·온도), 레이트 리미터, 모드 상태머신, 래칭 에러, `recover()` | 스펙 확정 (`docs/reflex-spec.md`) |
| L4 로봇 API | `sopo.robot.SopoRobot`: `connect/get_observation/send_action`, 보간, 정규화 | 예정 |
| L5 데몬 + IPC | `sopod`: 루프 + 상태 PUB + 명령 REP + 액션 SUB + 워치독 + 포트 락 | 예정 = "FCI" |
| L6 클라이언트 | `sopo.client` (파이썬), CLI(`sopo status/torque/recover/mode`), lerobot 어댑터, (선택) ROS2 브리지 | 예정 |
| L7 GUI | 웹(FastAPI + WebSocket + 브라우저) 또는 TUI — L6 위의 구독자 | 나중 |

횡단 관심사:
- **안전 설정의 잠금**: 토크 캡·리밋·reflex 임계값은 `safety.yaml`로 버전 관리하고, 변경은 명령 채널에서 "unlock → 변경 → 확인" 2단계 (Desk가 안전 설정 변경에 확인을 요구하는 것과 동일). 실행 중 상향은 거부.
- **모드**: `GUIDING`(토크 OFF, 손으로 가르치기 = 리더 모드), `MOVE`, `REFLEX`, `STOPPED`, `IDLE`. 모드 전환은 명령 채널로만.
- **블랙박스 로그**: 상태 스트림을 항상 디스크에 링버퍼로(최근 60초) — REFLEX 발생 시 앞뒤 구간 저장. Franka의 `last_motion_errors`에 해당.
- **식별**: udev 시리얼 → `/dev/sopo_follower` (완료). 데몬 시작 시 모터 모델/펌웨어/EPROM 설정을 기대값과 대조(설정 드리프트 감지).

## 3. GUI — 무엇을, 언제

**언제**: L5(데몬+상태 스트림)가 생긴 직후. 그 전엔 GUI가 버스를 직접 잡아야 해서 제어와 경쟁한다.

**형태**: 브라우저(Desk와 동일한 이유 — 설치 없음, 다른 PC/태블릿에서 열림, 제어 PC 화면 불필요). 1차는 `rich`/`textual` TUI로 CLI에 붙여도 충분.

**Desk에서 가져올 기능** (우선순위순):
1. 라이브 상태: 관절별 위치/부하/온도/전압, 루프 지터, 모드, 래칭 에러
2. Recover 버튼, 토크 ON/OFF(확인 필요), 소프트 정지(누르고 있는 동안만 = enabling 흉내)
3. GUIDING 모드 토글
4. 안전 설정 편집기 (잠금 해제 필요, 변경 이력 표시)
5. 캘리브레이션 위저드 = 05/06/09를 화면으로
6. 블랙박스 로그 뷰어

**절대 규칙**: GUI는 안전에 필요하지 않다. 닫혀 있어도 데몬이 모든 안전을 책임진다.

## 4. 진행 순서 (권장)

1. `sopo/reflex.py` (완료) → 08 통합(완료), 하드웨어 튜닝
2. `sopod` 데몬: 루프 + 모드 + 워치독 + 상태 PUB + 명령 REP + 포트 락. run_waypoints.py를 "웨이포인트를 액션 스트림으로 보내는 클라이언트"로 재작성 → 첫 번째 클라이언트
3. CLI (`sopo status`, `sopo recover`, `sopo torque off`) — 데몬 검증 도구
4. `SopoRobot` + lerobot 어댑터 = 클라이언트 위에서
5. 웹 GUI
