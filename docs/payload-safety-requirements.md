# 개발요구서 — 페이로드 기반 토크 안전망

작성: 2026-09-04 · 상태: 초안(승인 대기) · 관련: docs/reflex-spec.md, sopo/model/estimation.py

## 1. 배경과 의도

본 요구는 아래 다섯 가지 사용자 의도에서 출발한다. 이후 모든 요구항목(FR/NFR)은 이 의도 번호로 근거를 표기한다.

| # | 의도 | 현재 시스템과의 충돌 |
|---|---|---|
| I-1 | 실험 중 로봇팔이 **명령을 최대한 잘 추종**해야 한다 | 토크 캡 30%는 뻗은 자세에서 중력만으로 포화(G≈3.7 vs 캡 2.9 N·m) → 처짐·추종 저하 |
| I-2 | 향후 **물건을 잘 집을 만큼 힘**이 필요하다 | 30% 캡은 페이로드 여유가 없음 |
| I-3 | 현재 EE가 없어 **큰 토크는 불필요**, 모션 품질이 우선 | — (안전망이 이 상태도 자연히 커버해야 함) |
| I-4 | **모터 성능이 낮다** (저가 Feetech 서보) | 약한 모터를 캡으로 더 깎으면 성능 손실이 직접적 |
| I-5 | **쿡북을 순차 실행하는 것만으로** 외력을 적당한 정확도로 추정하고, 외력이 **행동의 의도보다 크면 reflex**가 떠야 한다. 학생에게 쉽게 인수인계 가능해야 한다 | 현재 임계는 코드 기본값(감으로 정한 고정 1.0 N·m), 도출 절차 없음 |

**종합**: 모터는 100% 힘을 발휘하게 하되(I-1, I-2, I-4), 안전은 "쿡북으로 사전에 정의한 최대 페이로드"를 초과하는 외력을 모델 기반으로 감지해 reflex하는 **능동 안전망**으로 담당한다(I-5). 수동 캡(30%) 중심 → 능동 감지 중심으로의 안전 철학 전환이다.

## 2. 현재 상태 (As-Is)

- 안전 주 방어선 = Torque_Limit 300‰(스톨 30%). EXTERNAL_FORCE는 고정 임계(warn 0.3 / trip 1.0 N·m)의 보조 감지기.
- 외력 추정기(model/estimation.py)는 동작하나, 실측 결과 감도 불확도 ±30~40%(세션 간 500g 복원률 62~81%), 정지 히스테리시스 오프셋 0.8~1.7 N·m 확인됨.
- 쿡북에 임계 도출·페이로드 정의·합격시험 단계가 없음.

## 3. 목표 상태 (To-Be)

### 3.1 판정 규칙 (핵심)

매 제어 사이클, 관절별 자세 의존 임계:

```
thr_j(q) = |extra_load_torque_j(q, m_max)| × k + floor_j

  m_max   : 쿡북에서 선언한 최대 페이로드 [kg]        (의도 I-5, I-2)
  k       : 실측한 추정 감도 불확도의 여유율 (예: 1.6)  — "추정이 ±40% 틀릴 수 있음을 인정"
  floor_j : 실측한 정지 잔차 노이즈·히스테리시스 바닥 [N·m]

|τ_ext,j| > thr_j 가 t_ext(0.3 s) 지속 → EXTERNAL_FORCE → REFLEX 홀드
```

"행동의 의도보다 큰 외력"의 수학적 번역: 접힌 자세에선 포락선이 작아 민감, 뻗어서 들 때는 의도된 부하만큼 관대해진다.

### 3.2 캡 해제 인터록

| 추정기 상태 | Torque_Limit | 의미 |
|---|---|---|
| 캘리브레이션(zero/dir/scale) + floor/k 실측 + tare 완료 | 상향 (전력 모드) | 안전망이 서 있을 때만 힘을 푼다 |
| 하나라도 미비 | 300‰ 유지 | 쿡북 미완료 팔은 자동으로 순한 모드 (I-5: 학생 보호) |

### 3.3 쿡북 파이프라인 (학생이 따라가는 순서)

```
[기존] 230 zero → 231 dir → 410 --scale      (자세·방향·환산 캘리브레이션)
[신규] 340_estimator_limits                   추정기 오차 한계 실측 (~20분)
        --phase floor : 정지 잔차 → floor_j
        --phase k     : 알려진 추 5회 반복 탈부착 → 복원률 분포 → k = 1/최저 복원률
[신규] 350_define_payload                     m_max 입력 → 포락선 미리보기
        + 실현성 검사("이 모터로 이 페이로드는 뻗은 자세 duty NN% 필요") (I-4)
        → arm.yaml payload 저장 → 전력 모드 활성
[신규] 360_payload_check                      합격시험: m_max 추 → 트립 없음 ✓
                                              m_max×k 초과 추 → 트립 ✓ + 감지 지연 표시
```

## 4. 기능 요구사항

| ID | 요구 | 근거 |
|---|---|---|
| FR-1 | arm.yaml에 `payload: {max_kg}` 섹션. 쿡북(350)만이 이 값을 기록한다 | I-5 |
| FR-2 | 데몬은 매 사이클 3.1의 thr_j(q)를 계산해 reflex에 전달한다 | I-5 |
| FR-3 | reflex.update()는 관절별 동적 임계 `ext_limit`를 받는다. 미전달 시 기존 고정 config로 폴백 | 호환성 |
| FR-4 | 쿡북 340: floor_j와 k를 실측·저장한다. k는 알려진 추 반복시험의 복원률 분포에서 자동 산출 | I-5 "적당한 정확도" — 오차를 재야 '적당함'을 정의 가능 |
| FR-5 | 쿡북 350: m_max 선언 + 실현성 검사(최악 자세 필요 duty가 한계 초과 시 경고·거부) | I-4, I-2 |
| FR-6 | 쿡북 360: 허용 추 통과 / 초과 추 트립을 실물로 증명하는 합격시험 | I-5 인수인계 신뢰 |
| FR-7 | 캡 해제는 3.2 인터록 조건 충족 시에만. 미충족 시 300‰ | I-1 + 안전 |
| FR-8 | 데몬은 목표 도착·정착 시 자동 tare한다 (EXTERNAL_FORCE가 1차 감지기로 승격되므로 히스테리시스 오탐 관리 필수) | 3.1 전제 |
| FR-9 | tare는 토크-ON 정지 상태에서만 허용 (현재 모드 무관 허용은 −G(q) 오염 위험) | 기지 결함 수정 |

## 5. 비기능 요구사항

| ID | 요구 | 수치 |
|---|---|---|
| NFR-1 | 감지 지연 (임계 1.2×초과 시 인가→홀드) | ≤ 0.5 s |
| NFR-2 | 오탐: 무접촉 왕복 10회(330 Phase A 방식) | 트립 0건 |
| NFR-3 | 학생 소요: 신규 쿡북 3종 합계, 안내문만으로 완주 | ≤ 40분 |
| NFR-4 | 신규 로직은 하드웨어 없이 합성 데이터로 테스트 가능 | 기존 관례 유지 |
| NFR-5 | pinocchio/캘리브레이션 부재 시 기존과 동일하게 동작(기능 축소, 안전 유지) | 회귀 0 |

## 6. 제약·전제

- Present_Load는 감도 불확도 ±30~40%, 히스테리시스 0.8~1.7 N·m의 저품질 토크 프록시다(실측). k·floor는 이를 흡수하는 장치이며 제거하는 장치가 아니다.
- 캡 상향으로 COLLISION(포화 기반)은 사실상 비활성화된다 → OVERTEMP, 모터 내장 과부하 보호, EPROM ceiling은 번아웃 최후선으로 반드시 유지.
- 감지→홀드까지 ~0.4 s 동안 모터는 전력을 낸다. 사람 손 근처 실험은 낮은 m_max로 운용하는 것을 운용 수칙으로 문서화한다.
